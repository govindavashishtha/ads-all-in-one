# Agent guide — rules for everyone building on this repo

Read [BUILD_PLAN.md](BUILD_PLAN.md) §0 first; it overrides everything else, this file included.

## Run it

```bash
make setup                 # uv sync --frozen --all-groups (Python 3.12)
make lint                  # ruff check + ruff format --check + mypy --strict
make test                  # all tests; integration needs TEST_DATABASE_URL (default: local 5432)
make test-unit             # no database needed
make migrate               # alembic upgrade head on DATABASE_URL
make migration m="..."     # new autogenerated revision (review it by hand!)
make bootstrap             # seed client + rules/limits v1 (no-op if already seeded)
make up / make compose-config
```

Default local DBs: `ads_autopilot` and `ads_autopilot_test` (user/password `ads`/`ads`) on
127.0.0.1:5432. The test DB is wiped (downgrade base → upgrade head) at the start of each run.

## Hard rules (enforced by tests where possible)

1. **Never invent business inputs** (§0.1, §25): target CPA/ROAS, caps, account ids,
   conversion events, model names. Use `MissingInputError("I-x", ...)` and stop.
2. **WriteConnector** may be imported only in `engine/executor/**` and
   `engine/pacing/emergency.py`; **platform SDKs** and **`connectors.money`** only in
   `engine/connectors/**`; **CLI** never imports DB code; only `engine/config.py` reads env vars.
   The API may import `engine.executor.plan` and `engine.executor.gate` (dry-run / write-gate
   status) but never a write module. `tests/unit/test_import_boundaries.py` fails the build otherwise.
3. **Money**: `Decimal`, major units, 2 dp outside connectors. Never floats for money.
4. **Time**: store UTC `TIMESTAMPTZ`; metric `date` / `ts_hour` are ad-account-local
   (`ts_hour` is the one naive timestamp column, by design — test-enforced).
5. **Idempotency**: upserts on natural keys (`ON CONFLICT`), `proposals.dedupe_key`,
   `job_runs (client_id, job, step, window_key)` (NULL step counts as a value).
6. **DB is the runtime source of truth** for mode, kill switch, rules, limits. Read the
   active `config_versions` row via `parse_rules` / `parse_limits`; never re-read the YAML.
7. **No live writes** before the Phase 3 gate (plan §0.5). Write tokens stay empty (the env
   credentials provider refuses `access=write` while they are), `HARD_MAX_MODE` stays
   `suggest`, and `clients.execution_enabled` defaults to false (D-28). Flip the flag only
   after Govinda signs off — never invent caps, account ids or targets. See D-27..D-34.
8. **Secrets**: only via `engine.credentials.get_credentials`. Settings hold them as
   `SecretStr`; never log or unwrap them elsewhere.
9. **Fixed seeds** for every Monte Carlo draw (§0.8).
10. **Schema changes**: edit `engine/db/models.py` + add a new Alembic revision; never edit
    `0001`. `alembic check` and `tests/integration/test_migrations.py` must stay green.
11. **Registry**: every `features` column must be a `source="features"` registry name and
    vice versa (`tests/unit/test_registry_schema.py`). Add the registry entry, model column
    and migration together.
12. Every task ends with `make lint && make test` green and the §23 acceptance checks.

## Decisions made in Phase 0 where the plan was silent or ambiguous

- ORM models live in `engine/db/` (§6 doesn't name a place); `engine/enums.py`,
  `engine/errors.py`, `engine/logging.py` added as shared modules.
- `BUILD_PLAN.md` moved to `docs/` per §6; root `BUILD_PLAN.md` is a symlink. v1.0 kept in
  `docs/BUILD_PLAN_v1.0.md`.
- **`/metrics` collision** (§17 lists both the time-series `GET /metrics` and Prometheus
  `GET /metrics`): time series = `/api/v1/metrics`; Prometheus = root `/metrics` on the API
  container (bearer `METRICS_TOKEN`), unreachable through the proxy (§18).
- `job_runs` unique key uses `NULLS NOT DISTINCT` so step-less runs are deduped (PG ≥ 15).
- `metrics_hourly.ts_hour` is `TIMESTAMP WITHOUT TIME ZONE` (account-local hour start).
- Status-like columns use CHECK constraints from `engine.enums`; `platform` and `entity_type`
  are native PG enums. `proposals.action` is free TEXT (validated in Python via `Action`).
- Added `evaluations UNIQUE (change_id, horizon_days)` for idempotency; `client_id` FK to
  `clients` on every table; `updated_at` on `clients` and entity tables.
- `audit_log` append-only via trigger (UPDATE/DELETE/TRUNCATE raise) + REVOKE from PUBLIC.
  Using a separate migration-owner role vs app role is a deployment decision (open).
- Seed YAMLs carry `inputs_confirmed: false`. Bootstrap refuses unconfirmed placeholders (and an
  empty `meta_conversion_action`) unless `APP_ENV=development`; it always requires
  `HARD_DAILY_CAP`/`HARD_MONTHLY_CAP` and checks every seed cap ≤ HARD (HARD = total).
- Search-term variables (`cost_30d`, ...) are computed in the `search_terms` job, not stored
  in `features` (search terms have no stable entity row). `add_negative` proposals use the
  latest `search_terms.id` as `entity_id` (Phase 2, [DECISIONS.md](DECISIONS.md) D-9).
- Emergency `change_log.proposal_id` is nullable (emergency / pause-all / rollbacks).
